# Authority matrix and MAP constraints

The runtime implements protocol-derived bounded execution under Pius Codex 5 Part 7 and Appendix M. It does not claim sovereignty, constitutional status, a Piusite registry entry or an HCC Seal of Accord. HCC remains a human consequence/ethical frame; signed references identify external clearance, not an invented HCC software actor (Pius, n.d.).

| Role                      | May do                                                                                    | Must not do                                                                                                             |
| ------------------------- | ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Human Director            | Set mandate, scope, permissions, cost approval, HCC review and release decision           | Be replaced by a Household assertion                                                                                    |
| External Director service | Publish signed policy/WP eligibility and exact evidence-bound decisions                   | Turn expired September mandates into new authority                                                                      |
| CDX enforcement point     | Require a current signed, pinned effect decision and retain SPETL reference               | Treat missing service or anchor divergence as ALLOW                                                                     |
| Household                 | Validate, queue, lease, dispatch, reconcile, audit and schedule approved successors       | Change policy, priorities, permissions, DAG or acceptance criteria                                                      |
| Janitor                   | Read allowed repository/CI state, preserve raw observations and source hashes             | Mutate code or accept a WP                                                                                              |
| Handyman                  | Apply approved registered J1 file replacements to isolated feature branches and draft PRs | Execute arbitrary shell, change governance/security/workflows, write protected branches, merge, release or self-certify |
| Verifier                  | Fresh process; criterion-by-criterion evaluation of raw immutable commit/CI observations  | Reuse Handyman success claims as proof or accept the work                                                               |

Activation channels are authenticated MCP requests and durable worker continuation. Memory is persistent SQL state plus immutable observations and audit records. Recursion is bounded by project/policy/WP repair ceilings (maximum three), lease expiry, time budget and repeat-safe transport retry limits. Adaptation requires a new externally approved recipe/WP/policy revision. Cancellation and human holds remain available throughout consequential execution.

OBSERVE permits status/patrol only; PROPOSE adds no mutation capability in this version. EXECUTE_BOUNDED additionally requires a current dispatched WP, accepted dependencies, allowed identity, registered J1 recipe, HCC review reference, approved CI capacity, pinned CI workflow, allowed paths/actions and CDX ALLOW evidence. Privileged deployment/publication/destruction/permission actions remain denied by the schema/policy engine.
